# Server Components must self-fetch `/api/*` for state a route handler mutates

M1's rule was "Server Components import `lib/api/resources/*` directly; never `fetch()` our own `/api/*`." M1 Task 13 found empirically that Next.js compiles Route Handlers and Server Component pages into separate module instances, so an in-memory mock store mutated by a route handler (e.g. `PATCH /api/account`) is invisible to a direct resource import from a page. The rule now splits in two: read-only catalog data still imports the resource directly, but any page reading state a route handler writes — cart pricing, orders, payment intents — must fetch its own `/api/*` endpoint via `headers()`/`cookies()`, following the pattern in `app/[locale]/account/page.tsx`. This is a mock-mode artifact that disappears at proxy cutover (ADR-0001) and costs one extra HTTP hop in dev, but the page pattern must exist now so no page silently reads stale state.
