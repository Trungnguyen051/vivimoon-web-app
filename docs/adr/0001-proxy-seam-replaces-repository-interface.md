# Proxy-seam architecture replaces the in-process repository interface

The frontend has no real backend yet, but must swap from mock to Vivimoon's real API resource-by-resource with no code changes at cutover. M1 removed the in-process `ProductRepository` mock/real swap point and replaced it with `/api/*` route handlers backed by per-resource modules (`lib/api/resources/<name>/{index,mock,upstream}.ts`), selected by `API_MODE_<RESOURCE>` env config. The repository interface was rejected because keeping it alongside the network seam would be two seams doing one job — this is the load-bearing architectural decision for the whole project. Resources migrate one at a time by flipping their `API_MODE_<RESOURCE>`; rollback is flipping it back, with no data migration since the frontend owns no data.
