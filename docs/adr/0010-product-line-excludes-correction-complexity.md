# Product Line will carry no correction-complexity signal; toric/multifocal readiness stays isolated in the Rx schema

**Status:** accepted — shipped in #28 (M6.5). `productLine` (`trongSuot/coMau/vanNhu`) replaced `type`/`lensTypeSchema`; `rx.ts` owns `rxLensTypeSchema` and every call site passes the fixed `RX_LENS_TYPE`.

Renaming the old `type`/`lensType` taxonomy to `productLine` (`trongSuot/coMau/vanNhu`, matching Vivimoon's real 3-way category split) removes `toric` and `multifocal` as taxonomy values — a live-site audit found zero toric or multifocal products across the whole catalog. We considered adding a replacement `correctionType` field to carry what those values used to mean for Rx validation, but rejected it: nothing on the real site resembles it, so it would be scaffolding for a taxonomy that doesn't exist yet, invented rather than modeled. Instead, ADR-0004's `cyl`/`axis`/`add` fields and `rxSchemaForLensType` stay exactly as they are, decoupled from any product-schema field (call sites pass the fixed `RX_LENS_TYPE`) rather than driven by real product data — dormant until a real toric or multifocal line exists, at which point wiring a signal back in is a call-site change, not a schema migration.
