# Product Line will carry no correction-complexity signal; toric/multifocal readiness stays isolated in the Rx schema

**Status:** proposed — tracked for implementation in #28 (M6.5). As of this writing, `type`/`lensTypeSchema` (`clear/colored/toric/multifocal`) still exists unchanged and `rxSchemaForLensType` is still called with `product.type` directly.

Renaming the old `type`/`lensType` taxonomy to `productLine` (`trongSuot/coMau/vanNhu`, matching Vivimoon's real 3-way category split) will remove `toric` and `multifocal` as taxonomy values — a live-site audit found zero toric or multifocal products across the whole catalog. We considered adding a replacement `correctionType` field to carry what those values used to mean for Rx validation, but rejected it: nothing on the real site resembles it, so it would be scaffolding for a taxonomy that doesn't exist yet, invented rather than modeled. Instead, ADR-0004's `cyl`/`axis`/`add` fields and `rxSchemaForLensType` will stay exactly as they are, decoupled from any product-schema field (call sites will pass a fixed value) rather than driven by real product data — dormant until a real toric or multifocal line exists, at which point wiring a signal back in is a call-site change, not a schema migration.
